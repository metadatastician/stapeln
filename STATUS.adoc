== What stapeln is

A *compiler from a visual topology to a verified deployment bundle*. You compose
a container stack on a drag-and-drop canvas; stapeln validates the topology,
scans it for security gaps, and lowers it to deployment artefacts. The design
document round-trips losslessly, so the canvas — not the generated files — is
the source of truth.

It is the designer for a six-repo ecosystem: *selur* (compose orchestration),
*vordr* (health/crash watching), *rokur* (secrets gate), *svalinn* (edge policy
gateway), *cerro-torre* (signing and provenance).

== The headline: it is now actually a compiler

As of 2026-08-27 the ruling is implemented in both directions.

[source,console]
----
POST /api/stacks/:id/generate?format=stapeln_bundle
----

emits nine files, and `Stapeln.BundleParser.raise_design/1` reads them back:

[source]
----
.gatekeeper.yaml   compose.example.toml   compose.toml   ct-build.sh
deploy.k9.ncl      manifest.toml          rokur.toml     vordr.toml
stapeln.design.json
----

The round-trip property `design == raise(lower(design))` is enforced by tests
(PR #41), and the guard is *mutation-verified*: deleting the design from the
emitted bundle turns 7 of 13 round-trip tests red.

=== Required metadata, and why

`generate/2` *refuses* to run without `author`, `email`, `license` and `owner`.
These four are not defaulted because `manifest.toml` is the file cerro-torre
reads to attribute a build. Defaulting them would be worse than leaving
`{{AUTHOR}}` in place: the placeholder guard would then pass on a bundle that is
placeholder-free and confidently wrong.

=== The AffineScript migration is 8.5% done, not complete

This is the correction most worth reading. All 47 `.affine` files exist and all
47 pass `affinescript check` — but that is *true and misleading*:

[source]
----
20,995 .affine lines
  19,203 (91.5%)  retained ReScript inside /* ORIGINAL RESCRIPT */ comments
   1,792 ( 8.5%)  real AffineScript
       0          function declarations, across ALL 47 files
----

It type-checks *because 91.5% of each file is an inert comment block*. Every
file carries a `TODO: port the remaining forms` marker; none is fully ported.

The cause was not that porting is hard. `tools/res-to-affine` silently degraded
to a line-regex scanner because its tree-sitter grammar was absent, reported the
engine it had been *asked* for rather than the one that ran, and exited 0 — so
the sweep logged 47 successes. Fixed at source in
https://github.com/hyperpolymath/affinescript/pull/730[affinescript#730].

*Porting is currently blocked* on
https://github.com/hyperpolymath/affinescript/issues/731[affinescript#731]:
nested constructor patterns emit identical guards, so later match arms are
unreachable. Nested patterns are the normal shape of decoders and of every TEA
`update` function, so porting more now would produce code that type-checks and
runs wrong.

One file, `ApiDecode.affine`, has been ported to completion by hand as a proven
exemplar — it type-checks, compiles, and carries no retained-ReScript block.

=== The empty-linter is advisory, by ruling

`Empty-linter (invisible characters)` appears as a green tick on every PR. It
emits `::warning` annotations and *never exits non-zero*, so it cannot fail.

That is *intended* — the owner ruled on 2026-08-27 that it should warn rather
than gate. Recorded here because a permanently-green check reads as assurance,
and it should not be mistaken for one.

Two caveats worth knowing:

* It runs in *384 of 644* repos, inlined as an independent copy in each repo's
  `dogfood-gate.yml` rather than called as a shared reusable.
* It scans neither `.affine` nor Ada, Nickel or Scheme. Since `.res` *is*
  scanned, the ReScript→AffineScript migration moves code *out* of its coverage.
