[[l-1--agpl-30-or-later-headers-inside-an-mpl-20-repository--medium]]
=== L-1 · AGPL-3.0-or-later headers inside an MPL-2.0 repository — MEDIUM

Nine files declare `SPDX-License-Identifier: AGPL-3.0-or-later`. All nine are GitHub
metadata templates, none is source code:

....
.github/settings.yml
.github/ISSUE_TEMPLATE/{bug_report,config,custom,documentation,feature_request,question}.yml
.github/DISCUSSION_TEMPLATE/{ideas,q-and-a}.yml
....

Evidence: `grep -rl "SPDX-License-Identifier: AGPL-3.0-or-later" .` (excluding `LICENSES/`).
Repo-wide SPDX distribution is `482 MPL-2.0 · 178 CC-BY-SA-4.0 · 9 AGPL-3.0-or-later`.

The pattern (AGPL confined entirely to `.github/` scaffolding) is consistent with template
drift from an estate-wide sweep rather than a deliberate relicensing. AGPL is strong
copyleft; carrying it unremarked inside an MPL-2.0 project invites a licence-compatibility
question that nobody actually intended to raise.

*RESOLVED 2026-08-07.* Owner ruling: stapeln is MPL-2.0 for code and CC-BY-SA-4.0 for
documentation, with no third licence. All nine identifiers changed to `MPL-2.0`, matching the
rest of `.github/` (the workflows were already MPL-2.0). Each file had exactly one identifier,
on line 1, so this was a value change — nothing was inserted, nothing shadowed. Policy is now
stated in link:LICENSING.adoc[`LICENSING.adoc`]. Verified: `491 MPL-2.0 · 179 CC-BY-SA-4.0`, no other
identifier in the tree.

[[l-2--two-divergent-copies-of-the-mpl-20-text--low]]
=== L-2 · Two divergent copies of the MPL-2.0 text — LOW

`LICENSE` and `LICENSES/MPL-2.0.txt` are both 16,726-byte MPL-2.0 texts with *different
checksums* (`815ca599…` vs `f75d2927…`). Evidence: `md5sum LICENSE LICENSES/MPL-2.0.txt`.
Harmless today (GitHub's `/license` API correctly reports `MPL-2.0` from `LICENSE`), but two
diverging canonical texts is a REUSE-compliance trap.

The divergence was trivial — a trailing space on line 38 and `http` vs `https` on line 360.

*RESOLVED 2026-08-07.* `LICENSES/MPL-2.0.txt` synced to `LICENSE`. `LICENSE` was chosen as
canonical because it is the file GitHub's `/license` API detects; leaving it untouched keeps
that detection stable.

[[l-3--licensesagpl-30-or-latertxt-may-be-unused-after-l-1--low]]
=== L-3 · `LICENSES/AGPL-3.0-or-later.txt` may be unused after L-1 — LOW

With L-1 resolved, no file in the tree is AGPL-licensed, so the AGPL text was an orphan and
REUSE would flag it.

*RESOLVED 2026-08-07.* `LICENSES/AGPL-3.0-or-later.txt` removed. `LICENSES/` now holds
exactly the two licences this project uses.

[[8-found-2026-08-27-shipping-the-bundle-compiler]]
== 8. Found 2026-08-27, shipping the bundle compiler

[[a-1--the-affinescript-port-contains-zero-functions--high]]
=== A-1 · The AffineScript port contains ZERO functions — HIGH

All 47 `.affine` files exist and all 47 pass `affinescript check`. Both facts are
true and together they are *misleading*:

[source]
----
20,995 .affine lines
  19,203 (91.5%)  retained ReScript inside /* ORIGINAL RESCRIPT */ comments
   1,792 ( 8.5%)  real AffineScript
       0          function declarations, across ALL 47 files
----

It type-checks *because 91.5% of each file is an inert comment block*.

*Cause, not effort.* `tools/res-to-affine` silently degraded to a line-regex
scanner because its tree-sitter grammar was absent (`tools/vendor/` is
gitignored by design, and the default grammar path resolves relative to the
CURRENT DIRECTORY). It then reported the engine it had been _asked_ for rather
than the one that ran, and *exited 0* — so the sweep logged 47 successes.

Fixed at source: https://github.com/hyperpolymath/affinescript/pull/730[affinescript#730].

*Scope.* The estate campaign covers ~3,996 files across ~80 repos. Any sweep run
without the grammar produced function-free skeletons and reported success.

Reproduce: `grep -chE '^\s*(pub )?fn ' frontend/src/*.affine | awk '{s+=$1} END{print s}'`

=== A-2 · Porting is blocked by unsound AffineScript codegen — HIGH

https://github.com/hyperpolymath/affinescript/issues/731[affinescript#731]: a
`match` whose arms differ only in a *nested* constructor emits identical guards,
so later arms are unreachable and the first arm's result is returned silently.
It type-checks; only the emitted JavaScript is wrong.

Found hand-porting `ApiDecode.affine`, where a `JFloat` id returned `Ok(2.7)`
from a function declared `-> Result<Int, String>` — a Float escaping into an Int
position.

Nested patterns are the normal shape of decoders and of every TEA `update`
function, so *porting more files now would produce code that passes review and
runs wrong.* One file (`ApiDecode.affine`) is ported to completion by hand as a
proven exemplar.

=== A-3 · `frontend/lib/bs/` is a stale, broken, tracked build — MEDIUM

A partial ReScript build of 30 of 47 modules whose `App.res.js` imports *nine
modules that do not exist in it* (`ApiClient`, `LoginPage`, `RegisterPage`,
`SettingsPage`, `AttackSurfacePage`, `PipelineDesigner`, `PipelineModel`,
`PipelineUpdate`, `ConversationalError`).

Nothing loads it — `index.html` loads `src/*.js`, which _is_ complete and
self-consistent — but it is tracked in git and will mislead the next reader into
thinking the app is broken. Delete it or regenerate it.

=== A-4 · The empty-linter does not scan `.affine` or Ada — MEDIUM

`Empty-linter (invisible characters)` is *advisory by owner ruling* (2026-08-27:
warn, do not gate), so its inability to fail is intended and is not itself debt.

The debt is coverage. Its extension list omits `.affine`, `.ads`, `.adb`, `.ncl`
and `.scm` while including `.res` — so *the ReScript→AffineScript migration moves
code out of its coverage*, and stapeln's 20,995 `.affine` lines are unscanned.

It also runs in only *384 of 644* repos, inlined as an independent copy in each
repo's `dogfood-gate.yml` rather than called as a shared reusable — so improving
it means touching 384 files.

== Cross-cutting note: the honest-red principle

Several items above (T-3, CI-3, CI-4) share one shape: *a gate wired so it cannot fail.*
The project's own doctrine is that a proof gate must be able to fail, and that an honest red
beats a fake green. Fixing these will make the board _look worse_ and _be_ better. That is
the intended direction.

A-1 is the same shape one layer up: not a gate that cannot fail, but a *tool* that
could not fail — it exited 0 after degrading. And A-4 is the deliberate exception,
where advisory-not-gating is the ruling rather than an oversight.
