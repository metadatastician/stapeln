= Badge Register — restore these

*Status as of 2026-09-22.* This is the working list of every badge stapeln wants on its
README, what each one asserts, and exactly what is needed to put it back. Six were removed
on 2026-08-07 because nothing in the repository verified them — *they are wanted, and this
file exists so they get restored as soon as the evidence is in place, not quietly forgotten.*

A badge is a public claim. The bar is simple: *the claim must resolve to something a
stranger can check, and that something must be this project.* A shields.io image with no
artefact behind it is decoration; worse, it is decoration that looks like assurance. A
badge that resolves to *somebody else’s* artefact is worse still — it is a false claim
wearing the costume of a verified one, and "does the link resolve?" will never catch it.

[[the-standing-rule]]
== The standing rule

*No compliance, certification, or registry-backed badge without a resolvable reference
that names this project.* Before adding a badge that requires external evidence, answer:
_if a stranger clicks this, do they reach something that could contradict the claim?_ If
the honest answer is no, the badge is decoration and does not go on the README. License
and descriptive technology badges may remain without link targets when their claims are
directly verifiable from this repository.

*And resolving is not enough.* "The link works" is a necessary test, never a sufficient
one — it is exactly the test that let project 8509 sit on thirteen READMEs. For any badge
backed by a registry, the check is that the record names *this repository*:

[source,console]
----
$ curl -s https://www.bestpractices.dev/projects/<id>.json | jq -r .repo_url
https://github.com/metadatastician/stapeln    # <-- must be this repo, not merely a valid page
----
