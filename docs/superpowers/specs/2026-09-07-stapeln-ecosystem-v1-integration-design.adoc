[[north-star]]
== North star

stapeln is a parts-assembly interface over OCI (the Kerbal / shape-sorter picture): a part
fills a slot; a stack is complete when every required slot is filled with compatible parts;
the designer is default-complete, default-safe, override-explicit (every override recorded
with a reason). Three personas must all succeed: the three-year-old who builds a working
stack from the palette; the web designer who sees their idea made visible; the head of ESA
who takes cerro-torre plus ATS2 extreme protection. Parts interoperate when they match OCI
or the joinery (groove from v1.1). The owner's satellites are only the first parts.

v1 is not the product. v1 is the first honest proof of the pivot "stapeln compiles →
bundle → parts consume", measured by a probe, on a CI board that is green or named-red in
all six repos.

[[parts]]
== Parts and parts descriptors (rulings 12 and D1)

A part without a groove manifest joins through a descriptor. *Ruling D1:* in v1 the
descriptors live in stapeln's catalogue, one file per known part at
`backend/priv/parts/<name>.toml`; from v1.1 each part owns its descriptor in its own repo
and stapeln's copy becomes a cache refreshed by PR. The compiler never touches the network;
SHAs are pinned in the descriptor.

Descriptors are plain TOML data files (quoted strings only, decimal numbers only, dates as
RFC 3339 strings, no literal strings, no `[section]` re-opening: a plain data tree that a
later emitter can serialise into another form unchanged), read by today's Elixir TOML
decoder. They are stapeln's own files, not A2ML or `.deed` documents. The grammar session
confirmed on 2026-09-08 that no routed multi-surface form exists for them to target, so
open question Q1 in <<decisions>> reduces to the syntax choice A6 that also covers
`stack.lock` (<<stack-declaration>>).

[source,toml]
----
# backend/priv/parts/rokur.toml
[part]
name = "rokur"
slot = "secrets-gate"
interface = "oci"                 # "oci" or "groove"
model_component = "Rokur"         # Model.res tag; "" when the palette cannot place it yet
repo = "https://github.com/metadatastician/rokur"
sha = "0000000000000000000000000000000000000000"   # 40 hex, pinned, refreshed by PR
image = ""                        # digest-pinned OCI ref when one is published

[part.build]
containerfile = "Containerfile"
context = "."

[part.runtime]
ports = [{ port = 9090, protocol = "tcp", transaction = "secrets-gate API + /health" }]
mounts = ["./rokur.toml:/app/rokur.toml:ro,Z"]
command = ["--config", "/app/rokur.toml"]           # appended to the image ENTRYPOINT
env = ["ROKUR_API_TOKEN", "ROKUR_REQUIRED_SECRETS"]  # names only; values never in a descriptor
health = { path = "/health", port = 9090 }

[part.contract]
consumes = ["rokur.toml"]
manifest_url = ""                 # groove manifest, when the part publishes one (v1.1)
----

svalinn's descriptor differs in: `slot = "edge-gateway"`, `model_component = "Svalinn"`,
`image = "ghcr.io/metadatastician/svalinn@sha256:7f28b132…"` (exists), port 8000 today,
`env = ["SVALINN_GATEKEEPER_CONFIG"]` set to `/app/.gatekeeper.yaml`, mount
`./.gatekeeper.yaml:/app/.gatekeeper.yaml:ro,Z`, `consumes = [".gatekeeper.yaml"]`.

v1 ships exactly two descriptors (rokur, svalinn: the two consumers). selur, vordr and
cerro-torre get descriptors in v1.1 with their consumption; until then a placed Vordr,
Selur or CerroTorre component is recorded in the stack declaration with
`source = "design-only"` and is not run by the smoke. Every port carries the protocol and
the transaction it serves (network doctrine of 2026-09-02); rokur's 9090 (Prometheus's
default) and svalinn's 8000 (a banned class) are re-assigned by the doctrine's procedure in
one PR per repo (<<cures>>, W13), and the descriptor is the single place the number lives.

Loader: `Stapeln.Parts.load!/0` reads every file in `priv/parts`, raises on a missing
required field, a `sha` that is not 40 hex, a `slot` outside the table, or a duplicate
name. Unknown keys raise (the same allowlist discipline as rokur's loader).

The compiler is two-stage so that the stack declaration is the single source of truth by
construction: *lower* (`stapeln.design.json` + the descriptor catalogue → the stack record
tree), then *emit* (the record tree → `stack.lock`, `compose.yaml`, the `compose.toml`
substitutions and the per-part config files). No emitter reads a descriptor directly; if a
value is not in the declaration, it is not in the bundle.

[[compose-yaml]]
=== `compose.yaml`

The existing `:podman_compose` output for design services plus one service stanza per
descriptor-backed part placed in the design: `build: {context: ./parts/<name>, dockerfile:
<containerfile>}` when `image` is empty, else `image:` with the digest; `ports`, `volumes`
(the consumed file, read-only), `command`, `environment` (names only, values from the
runner's env), `healthcheck` from `health`. The bundle carries no `./parts/<name>` sources;
materialising them (clone at the declared SHA) is the runner's job (<<smoke>>).

[[stack-declaration]]
=== The stack declaration (ruling D3, applied through the grammar answer): `stack.lock`, stapeln-owned

*Ruling D3 (owner, 2026-09-08):* the stack declaration is not TOML, JSON or a file outside
the bundle chosen by stapeln. It is expressed in the estate's system-of-systems
declarative document — the `.a2ml` document now migrating to `.deed`, Idris2-based, the
type-safe single source of truth — and its grammar belongs to the session formalising the
grammar and dialects. stapeln invents no grammar. The draft's TOML sketch survives only as
the *field inventory* the declaration must carry.

*Measured answer from that session (2026-09-08, G1–G6, recorded in <<decisions>>):* the
declaration cannot be a `.deed` today and must not pretend to be one. No `.deed` grammar
has landed. The only runnable gate, `a2ml/actions/validate/validate-a2ml.sh`, recognises
four identity shapes and no s-expression form, and reports identity and version as
warnings (exit 0) unless run with `INPUT_STRICT=true`. There is no declaration site for
slot or assembly vocabulary; it belongs in the estate deed (`estate_chora.deed`), never in
stapeln. The A2ML Record Dialect specification is under an open owner ruling to withdraw,
supersede or scope it, and is not to be cited as cover for a `key = value` surface. The
"three-tier routed TOML → JSON → scm" form the owner recalled does not exist: the three
are a record-dialect specification, an unstable ReScript-prototype JSON dump and an
inbound importer of legacy `.scm` files, and `@profile` is inert under base conformance
(discrimination, not routing). The instruction to stapeln: keep the declaration as an
explicit dependency, own the interim file, emit neither `.deed` nor `.a2ml`, never write
TOML records and call them A2ML, and migrate when the grammar lands.

*Decided here (stapeln's side of the seam):*

* File 11 is `stack.lock`: the generated, pinned, stapeln-owned lock file named by
  ruling 2, in the role `Cargo.lock` plays for a crate (a TOML lock file nobody mistakes
  for a manifest). It is *not* an A2ML document and *not* a `.deed`, and its header says
  so. It carries no `@profile` line, claims no conformance class and is checked by no
  `a2ml validate` step. The `stapeln/stack` profile proposal of the first version of this
  section is withdrawn; nothing under `a2ml/` is touched.
* Syntax: plain TOML data (assumption A6, Q1 option a in <<decisions>>; the owner may
  choose otherwise), read by the Elixir TOML decoder stapeln already depends on. Only
  quoted strings, decimal integers, RFC 3339 timestamps as strings, arrays, inline tables
  and the `[[part]]` array-of-tables, so the record tree is a plain data tree a later
  emitter can serialise into the deed form unchanged. Sub-tables under an array-of-tables
  element are avoided: nested data on a `[[part]]` uses inline tables.
* Migration: when the `.deed` grammar lands, `mix stapeln.bundle` emits the same record
  tree in the head form that grammar defines (the owner's three are `(estate-deed`,
  `(repo-deed` and `(estate-atlas-deed`; which one, if any, fits a per-stack declaration
  is that grammar's call, not stapeln's) and the deed validator becomes the gate.
  `stack.lock` stays the pin record for as long as a consumer reads it. The change is
  confined to one emitter and the fixtures.
* Vocabulary: the slot ids and part fields below are stapeln's field inventory, not an
  estate declaration. If the estate deed later declares slot or assembly vocabulary,
  stapeln's inventory is reconciled to it, not the other way round.
* Required tables: `stack`, `slots`, and the array-of-tables `part`. Every slot key is
  present in `[slots]` even when empty (the missing-part signal is structural, not
  inferred). `verified = false` is present on every part in v1 so the designer can say
  "unverified" honestly rather than omit the fact.
* Field inventory (the record tree):

*Reading it in v1, honestly labelled:* stapeln's own contract test
(`stack_declaration_test.exs`) decodes `stack.lock` with the Elixir TOML decoder and
checks structure: the three tables present, all twelve slot keys present, every part's
slot in the slot table, every sha 40 hex, `design_sha256` equal to the hash of the
emitted design, and a header that names the file as stapeln's own and not A2ML or deed.
The same assertions run in the smoke as `mix stapeln.bundle --check out/bundle/stack.lock`
(<<smoke>>). That test is the only thing carrying slot completeness in v1, and it stays
when the deed grammar lands. No estate validator gate is claimed: `validate-a2ml.sh`
without `INPUT_STRICT=true` is a formality, and this file is not its input.

*Owned by the grammar session, not by stapeln (the explicit dependency):* the `.deed`
grammar and its head forms; the estate rename timing; the deed validator; any estate
declaration of slot or assembly vocabulary. Six questions were sent on 2026-09-08 and
answered the same day (<<decisions>>, G1–G6); the answers are applied above. The one item
still open on stapeln's side is A6, the syntax of its own files until the migration.

*v1.1:* consumers read `stack.lock` through the TOML readers their runtimes already have
(rokur reads TOML today); cerro-torre's `manifest.toml` pins the sha256 of the emitted
`stack.lock` bytes; `stack.kube.yaml` is emitted from the same record tree. Validation
through estate bindings arrives with the deed form, not before.

Rules: a design with two parts in a max-1 slot still emits (v1 has no engine) but the
designer's existing `validation_engine` port-conflict rule refuses `compose.yaml` when two
parts publish the same host port.

[[seam]]
== The template seam: make the emitted files loadable, and prove it on both sides

. `rokur.toml` template → exactly rokur's allowlist: `[metadata] name, version`;
  `[server] host = "0.0.0.0", port = <declared port>, health_path, ready_path`;
  `[secrets] required = [], sources = ["env"]`; `[rate_limit] window_ms, max,
  auth_fail_max`; `[policy] backend = "builtin", timeout_ms`; `[audit] enabled, path,
  request_log`. No `backend` key, no `listen`.

  `auth.public: ["/healthz", "/health"]`; `auth.authenticated: ["/v1/*", "/verify",

  dropped `trust / validation / cors / logging` content describes features the MVP gateway
  does not implement (trusted signers, attestations); it moves to stapeln docs as
  "gateway policy roadmap" (assumption A4), never into an emitted file.
. `compose.toml` template: image refs and ports come from the stack declaration via new
  substitution tokens (`{{ROKUR_IMAGE}}`, `{{ROKUR_PORT}}`, `{{SVALINN_IMAGE}}`,
  `{{SVALINN_PORT}}`); the bundle test's dead-namespace assertion is replaced by "no
  `ghcr.io/hyperpolymath` anywhere in the bundle".

[[rules]]
== Rules vocabulary (ruling 6: v1 = vocabulary only)

`backend/priv/rules/v1.toml`, parsed by a test and enforced by nothing until v1.1. It is
written as the same plain TOML data as the descriptors (<<parts>>), so the same syntax
choice (A6 in <<decisions>>) covers it.

[source,toml]
----
[rules]
schema = 1

# kind = cardinality | exclusion | compatibility | topology
[[rule]]
kind = "cardinality"
slot = "runtime"
min = 1
max = 1
severity = "error"
hint = "A stack runs on exactly one runtime; drag podman, nerdctl or docker into the runtime slot."

[[rule]]
kind = "cardinality"
slot = "firewall"
min = 0
max = 1
severity = "warn"
hint = "No firewall part is placed; the stack is shown as missing one (v1 ships none)."

[[rule]]
kind = "compatibility"
part = "selur-compose"
requires = ["selur"]

  document today, and which file is its authoritative grammar? *No.* No `.deed` grammar has

  There is no declaration site for slot or assembly vocabulary; it belongs in
  `estate_chora.deed` when that exists, never in stapeln.
* G4 What must stapeln not do? Touch the `.a2ml`/`.deed` grammar, manifests, validators or
  profiles; land any part of the rename (prepare but land nothing); overwrite either of the
  two canonical stapeln trees (merge, never overwrite).
* G5 Is there a validator today? *Only `validate-a2ml.sh`:* four identity shapes, no
  s-expression form, identity and version reported as warnings (exit 0) unless
  `INPUT_STRICT=true`; two gaps (identity, `:schema-version`) to be patched together when
  the grammar lands. stapeln's contract test is the only thing carrying slot completeness.
* G6 Does the "three-tier routed TOML → JSON → scm dialect with header directions" the
  owner recalled exist? *No.* The three are separate: the record-dialect specification, an
  unstable ReScript-prototype JSON dump (`docs/AST-JSON.adoc`) and `scm2a2ml`, an inbound
  importer of legacy `.scm` files; `@profile` is inert under base conformance, so nothing
  routes on a header. Keep the explicit-dependency form and cite nothing.
